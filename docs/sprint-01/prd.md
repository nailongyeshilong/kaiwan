# Sprint 01 PRD

> 项目：开玩（KaiPlay）
> Sprint：01
> 文档版本：V1.0

---

# 1. Sprint 目标

Sprint 01 的目标是交付《开玩》的第一期可用版本（MVP 基础闭环）。

用户应能够完成以下完整流程：

启动 App

↓

发现卡池为空

↓

进入游戏库新增游戏

↓

返回首页执行抽取

↓

查看今日结果

↓

查看历史记录

本期不追求复杂玩法扩展，优先保证业务正确、架构稳定、数据可持久化。

---

# 2. Sprint 范围

Sprint 01 包含以下一级页面与能力：

* 首页
* 游戏库
* 游玩记录
* 设置
* 本地数据存储
* 本地图片录入与复制到应用沙盒

---

# 3. Sprint 核心交付

## 3.1 首页

首页是 Sprint 01 的核心页面。

本期首页必须支持：

* 展示今日抽取结果
* 展示今日剩余抽取次数
* 展示卡池游戏数量
* 点击“开玩”执行抽取
* 当卡池为空时提示用户并引导进入游戏库
* 将当天抽取状态持久化保存

本期首页抽取流程要求：

* 点击“开玩”后进入抽取流程
* 页面应提供明显的反馈感
* 允许使用轻量版动画实现，不要求一次完成最终复杂特效
* 抽取完成后立即展示结果并保存状态

本期首页不要求：

* SSR / UR / 品质系统
* 标签系统
* 音效系统
* 粒子级复杂特效

## 3.2 游戏库

游戏库用于维护抽取卡池。

本期必须支持：

* 查看全部游戏
* 新增游戏
* 编辑游戏
* 删除游戏
* 游戏名称唯一校验
* 从系统相册选择封面图片
* 选择后将图片复制到应用沙盒，仅保存本地路径

本期不要求：

* Steam 导入
* 自动获取封面
* 标签、分类、评分、评论

## 3.3 游玩记录

游玩记录页用于查看历史抽取结果。

本期必须支持：

* 查看历史记录列表
* 展示日期
* 展示游戏名称
* 展示游戏封面
* 展示抽取时间

游玩记录在 Sprint 01 中为只读页面。

## 3.4 设置

设置页在 Sprint 01 中仅包含：

* App 版本号

# 4. 业务规则

## 4.1 抽取规则

Sprint 01 必须严格遵循以下规则：

* 每天最多抽取 3 次
* 第一次抽取生成今日推荐游戏
* 第二次、第三次抽取视为重新抽取
* 第三次抽取完成后锁定当天最终结果
* 当天锁定后不可继续抽取
* 次日自动恢复 3 次抽取机会

## 4.2 卡池为空

当卡池为空时，用户点击“开玩”后：

* 提示“当前卡池为空，请先添加游戏。”
* 引导用户进入游戏库

## 4.3 游戏名称唯一

游戏名称必须唯一。

若新增或编辑后名称与已有游戏重复：

* 禁止保存
* 明确提示用户

## 4.4 删除游戏

删除游戏后：

* 从当前卡池移除
* 不影响历史记录
* 不修改已保存的当天抽取记录

## 4.5 编辑游戏

允许编辑：

* 游戏名称
* 游戏图片

编辑后：

* 游戏库立即更新
* 首页卡池立即使用最新数据
* 历史记录仍保留抽取当时的数据快照

## 4.6 数据持久化

Sprint 01 必须保证以下数据本地持久化：

* 游戏库
* 游玩记录
* 当日抽取结果
* 当日剩余抽取次数
* 当日锁定状态

用户关闭 App 并重新进入后，上述数据必须恢复。

# 5. 视觉与交互要求

Sprint 01 的 UI 风格要求如下：

* 整体采用深色、Steam Inspired、克制的游戏平台风格
* 保持 Material 3 体系
* 使用统一 Theme 与 Design Token
* 首页突出“抽卡主场景”
* 其他页面保持简洁、高效、信息清晰

说明：

当前设计规范文档中存在 “AI Gacha”“品质”“标签” 等扩展设定。

Sprint 01 仅采纳其视觉语言，不采纳这些额外功能设定。

---

# 6. 技术与架构范围

Sprint 01 开发必须遵循以下技术约束：

* Feature First
* MVVM
* Repository Pattern
* 单向数据流
* Riverpod 管理页面状态
* GoRouter 管理路由
* Hive CE 负责本地存储
* Image Picker 负责图片选择
* Path Provider 负责应用沙盒目录

禁止：

* UI 直接访问存储
* Provider 直接操作文件
* 绕过 Repository 访问数据
* Feature 之间直接调用 Provider

---

* 云同步

* Steam 导入
* 自动封面抓取
* 分享功能
* AI 推荐
* 游戏时长统计
* 排行榜
* 社区功能
* 多语言支持
* 游戏标签
* 游戏分类
* 品质稀有度系统
* 成就系统
* 深色模式切换
* 数据导入导出

---

# 8. 本期完成定义

当以下条件全部满足时，可认为 Sprint 01 完成：

* 四个一级页面全部可访问
* 游戏库 CRUD 可用
* 首页抽取流程可用
* 每日 3 次抽取规则正确
* 历史记录可查看
* 设置页可显示版本号
* 本地数据可持久化
* `flutter analyze` 无错误
* 与本期功能直接相关的验收项全部通过

---

# 9. 开发优先级

Sprint 01 推荐开发顺序如下：

1. 基础项目架构与依赖接入
2. 本地存储与 Repository
3. 游戏库功能
4. 首页抽取功能
5. 游玩记录
6. 设置页
7. 首页交互与动画补齐
